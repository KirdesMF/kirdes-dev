# Architecture

Vertical-by-domain structure. Rule: code that changes together lives together.

## Current/target folders

```txt
src/
  app-shell/
  navigation/
  theme/
  typography-effects/
  visual-effects/
  graphics-engine/
  i18n/
  shared/
  infrastructure/
  design-system/
  pages/
```

## Placement rules

1. Domain-specific code -> owning vertical.
2. Shared business logic across verticals -> `src/shared/`.
3. Cross-cutting wiring/config/adapters -> `src/infrastructure/`.
4. Truly generic UI primitives -> `src/design-system/`.
5. Keep verticals flat first. Nest only when big.
6. No barrel `index` files.

## Import rules (process, not lint-enforced)

- Vertical can import:
  - same vertical
  - `shared/`
  - `infrastructure/`
  - `design-system/`
- Vertical cannot import other vertical directly.
- If two verticals need same code, extract to `shared/`.

## Migration strategy

Note: `src/types/msdf-fonts.d.ts` is auto-generated by `plugins/msdf.ts` during build. Do not delete manually.


- Move one vertical at time.
- Small commits.
- Fix imports immediately after move.
- Run `bun run build` after each vertical.
